# Retrieval experiment
Thirty fixed queries cover ten job families with three formulations each. Forty fictional records repeat these families across eligibility conditions. All active members of a queried family count as relevant. Labels are binary and many records share descriptions. Perfect performance on this small family-retrieval exercise is easy to achieve and does not predict behavior with real job seekers.

Measured NDCG@10 was 0.567 for keyword, 1.000 for semantic, 1.000 for hybrid and 1.000 for personalized hybrid after restoring cosine magnitude and bounding personal signals (original 0.642). The profile used Python and SQL and preferred retrieval. Profile overlap can overwhelm query relevance. The labels measure job family relevance and do not measure individual preference satisfaction.

[Raw metrics](measured-results.json) include recall, precision, MRR, NDCG and latency. Latencies cover local in-process queries on embedded PostgreSQL, including cached repeated encodings in later strategies. They exclude HTTP and browser time. Four strategy runs each execute thirty queries sequentially. Use an isolated database with the default 40 records. Run scripts/evaluate.py and open Evaluation lab. Live LLM quality, throughput under concurrent load, independently labeled eligibility accuracy and unsupported-claim rates remain unmeasured.

## Independent named-target exercise
The original regression fixture remains unchanged. After freezing the revised formula, we authored 12 distinct editorial records and 30 binary target judgments separate from the seeded job-family generator. The queries include exact terms, paraphrases, multi-target overlaps and competing roles. The background contains plausible unjudged matches. Scores reflect retrieval of named targets and do not estimate exhaustive real-world relevance. The authors were not independent human assessors. No reranker tuning followed this result.

Across 1,052 records, named-target NDCG@10 was 0.454 keyword, 0.987 semantic, 0.987 hybrid and 0.987 personalized. See editorial-results.json for each query, target, returned ID and metric. Ranking instrumentation uses no external model calls. The separate HTTP workload measured four concurrent clients on four repeated warm queries with DB_POOL_SIZE=1 and DB_MAX_OVERFLOW=0 to suit the embedded PostgreSQL runtime. See http-load.json for hardware, percentiles, elapsed time and successes. These timings exclude neither HTTP nor queueing but do exclude warm-up.

The first expanded import took 27.15 seconds. The second saw the same 1,012 records, changed zero and took 3.99 seconds. The refresh test edits text under the same external key, verifies stable ID and changed embedding, retrieves the new term, then expires the job and verifies exclusion.

## Graded evaluation
Run scripts/graded_eval.py after scale_seed.py. The authored qrels contain 100 paraphrases in 25 intent clusters across twelve editorial targets. Primary targets earn grade 3, alternatives grade 1. Four paraphrases share each cluster’s judgments, so these are not 100 independent information needs. Two fixed skill profiles alternate. Mode and monthly stipend restrictions use verified_only. The labels and formula were fixed before this evaluation. Unjudged plausible background jobs receive zero target gain. No users supplied preference-satisfaction judgments.

NDCG@10 was 0.6599 for keyword, 0.8752 for semantic, 0.8752 for hybrid and 0.8760 for personalized. The earlier strict-only keyword run returned zero rows. A plain-language fallback recovered results. Applying that fallback inside fusion reduced hybrid NDCG@10 to 0.8353 on this fixture, so final fusion retains the original strict lexical branch. The two earlier runs are archived under graded-results-strict-keyword.json and graded-results-relaxed-fusion.json. Every strategy returning rows recorded zero checked status/mode/salary violations on this split. The small personalized difference does not establish a statistically reliable gain. See graded-results.json for per-query IDs, recall, MRR, graded NDCG, latency and category means. Contradiction resolution, negative skills, currency uncertainty and adversarial behavior are not all represented in these graded judgments.

The deterministic agent exercise (scripts/agent_eval.py) invoked the expected tool on seven of seven turns and retained constraints on four of four probes. All 120 checked title, company, salary and URL values matched stored records. This measures record fidelity rather than factual accuracy of generated free text. Separate protocol tests exercise mock refusal, invalid envelopes, malformed JSON, wrong tool names, timeouts and injected listing text. Hosted tool-selection and generation quality remain not evaluated.

## Lexical and semantic complementarity
The original 100 graded queries had identical top-ten lists for semantic and hybrid search in 100 of 100 cases. The separately authored 24-query diagnostic adds exact skill names, abbreviations, rare terms, misspellings, paraphrases, explicit work-mode/exclusion constraints and salary checks. Relevance uses the existing fictional editorial targets and author judgments. There are no independent human raters.

On the 1,052-record index, NDCG@10 was 0.8371 for keyword, 0.9308 for semantic, 0.9462 for hybrid and 0.9480 for personalized. All four strategies recorded zero checked constraint violations. Fusion changed one top-ten list and moved the relevant database reliability listing up for “failover,” adding 0.369 NDCG on that query. The mean paired change was +0.0154. A descriptive query bootstrap interval was [0.0000, 0.0461]. The interval includes zero and the result rests on one query. This supports an example of complementarity, with limited evidence for a general lift. The typo subset does not establish dedicated spelling correction. See fusion-results.json for per-query ranks and category breakdowns.
